# GNOMES — Android / libGDX

Idle/incremental-игра про живую гномью шахту. Базовая экономика похожа на merge/idle: покупаем гномов, усиливаем их и объединяем 10 единиц текущей ступени в 1 следующей. Но сама шахта теперь не абстрактное поле: это процедурный лабиринт туннелей, по которому реально ходят гномы и враги.

## Alpha 0.2 — Tunnel Mine

- Новое главное меню в структуре DOT//CORE: `Играть`, `Продолжить`, `Сохранения`, `Настройки`, `Об игре`, `Выход`.
- 5 независимых слотов сохранений с удалением и продолжением последнего слота.
- Каждый уровень генерирует собственную детерминированную сеть туннелей.
- Гномы и враги используют pathfinding по графу шахты. Они больше не перемещаются по сплошному камню напрямую.
- Рудные жилы находятся в стенах карманов/тупиков туннеля, а не случайно валяются на открытом поле.
- После очистки уровня открывается следующая глубина с новой шахтой.
- Полностью переделана процедурная анимация гномов:
  - отдельный цикл ходьбы с постановкой ног и покачиванием корпуса;
  - борода и шапка участвуют в движении;
  - добыча имеет фазы замах → удар → отдача;
  - две кирки анимируются независимо;
  - буровая имеет вращающийся/вибрирующий бур;
  - экскаватор получил сочленённую рабочую стрелу;
  - железный гном-голем двигается и атакует как тяжёлая единица;
  - мешок с рудой физически покачивается при переноске.
- Полностью переделано разрушение пород:
  - несколько слоёв камня;
  - видимые минеральные жилы;
  - трещины растут по мере потери HP;
  - появляются выбитые куски;
  - каждый удар даёт отдачу, пыль, осколки и screen shake;
  - регенерирующие породы имеют собственную пульсацию.
- Враги получили разные типы движения и атак:
  - бесы прыгают, машут крыльями и тянутся к сундуку;
  - демоны двигаются тяжело и атакуют рывком;
  - големы собраны из подвижных массивных частей;
  - огненные, водные и каменные големы имеют разные эффекты;
  - боссы имеют ауру, корону и собственный масштаб.
- Обвалы, провалы, лава и поток воды теперь имеют предупреждение и визуальную фазу срабатывания.
- Факелы, пыль, глубинное освещение и фактура стен делают шахту визуально читаемой и живой.

## Игровые системы

- 6 ступеней гномов:
  1. обычный гном;
  2. продвинутый гном;
  3. гном с двумя кирками;
  4. гном на буровой;
  5. гном на экскаваторе;
  6. железный гном-голем.
- 10 гномов текущей ступени объединяются в 1 следующей ступени.
- У каждого типа свои добыча, скорость, боевой урон и грузоподъёмность.
- Породы: камень, серебро, золото, алмаз, обсидиан, древний кристалл.
- Обсидиан и древние кристаллы регенерируют. Для них нужен mining DPS выше регенерации.
- Добыча становится ресурсом игрока только после того, как гном физически принесёт её в сундук.
- Сундук неразрушим.
- Бесы и Король бесов воруют накопленные ресурсы из сундука.
- У сундука можно нанять и усиливать гнома-стража.
- Враги: бес, демон, каменный, водный и огненный големы, Король бесов, Король демонов, Король элементалей.
- При появлении угрозы гномы бросают добычу и идут в бой.
- Артефакты дают постоянные бонусы.
- Система рун работает на классах гномов, глобальных улучшениях, артефактах, сундуке и страже.
- Большая нижняя кнопка ускоряет симуляцию ×4, пока удерживается.

## Технологии

- Java 17 для исходников
- libGDX 1.14.2
- модули `core` + `lwjgl3` + `android`, по той же схеме, что DOT//CORE
- Gradle 9.5.0 + Android Gradle Plugin 9.3.1
- Gradle Daemon JVM 25
- Android SDK 36
- GitHub Actions компилирует `:core:compileJava` на каждый push в `main`

Персонажи и окружение пока рисуются процедурно через libGDX. Для текущей стадии это намеренно: анимационные тайминги, пропорции и читаемость можно менять без перерисовки десятков sprite sheet. Когда движения и масштаб камеры будут окончательно утверждены, отдельные элементы можно заменить финальным арт-паком без переписывания симуляции.

## Запуск на Ubuntu

```bash
./gradlew -PskipAndroid :lwjgl3:run
```

## Android

```bash
./gradlew :android:assembleDebug
./gradlew :android:installDebug
```

APK:

```text
android/build/outputs/apk/debug/android-debug.apk
```

В Android Studio открыть корень проекта, дождаться Gradle Sync и запускать модуль `android` на подключённом устройстве.

## Следующий визуальный проход

После живого теста на телефоне имеет смысл править уже не архитектуру, а ощущения: размеры персонажей относительно туннеля, длительность удара, плотность частиц, скорость перемещения, частоту врагов и глубину screen shake. Затем добавить полноценный SFX/музыкальный слой и, если процедурный стиль перестанет устраивать, заменить персонажей/машины на финальные sprite sheet без изменения игровой логики.
